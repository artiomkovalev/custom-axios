# Архитектура обработки запроса

Схема прохождения HTTP-запроса через внутренние модули библиотеки.

## Порядок выполнения

```text
1. Вызов метода (get, post, request)
   │
   ├──► Check Offline Status (Проверка navigator.onLine)
   │
   ├──► Circuit Breaker (Проверка состояния цепи для serviceKey)
   │     │
   │     ├── (Цепь открыта) ──► Вызов fallback или ошибка
   │     └── (Цепь закрыта) ──► Продолжение
   │
   ├──► Axios Request Interceptors
   │     ├── loggingInterceptor
   │     └── authInterceptor (Подстановка Bearer-токена)
   │
   ├──► Axios Retry (Повторы при 429 или сетевых сбоях)
   │
   ├──► Axios Cache Interceptor (Проверка кеша для GET)
   │
   ├──► Сетевой запрос
   │
   ├──► Axios Response Interceptors
   │     ├── loggingInterceptor
   │     └── refreshInterceptor (Обработка 401 и установка очереди)
   │
   └──► Error Transformer (Вызов defaultErrorTransformer или customErrorTransformer)
```

## Механизмы защиты

### Circuit Breaker
Предотвращает повторную отправку запросов к сервису, находящемуся в сбойном состоянии. Если за контрольный интервал времени больше 50% ответов вернулись с ошибкой, прерыватель переходит в состояние `OPEN` на 15 секунд. В этом состоянии сетевые запросы не отправляются, а сразу вызывается `fallback` или выбрасывается ошибка.

### Axios Retry
Повторяет сетевые запросы при отсутствии связи или получении статуса `429 Too Many Requests`. Задержка между попытками рассчитывается по экспоненциальной шкале.

### Refresh Interceptor
Блокирует отправку повторных запросов с истекшим токеном. При получении первого ответа `401 Unauthorized` запускается процесс обновления токенов. Все параллельные запросы приостанавливаются до завершения операции обновления, после чего выполняются повторно с новым токеном.
